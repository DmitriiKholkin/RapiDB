# Предрелизное ревью RapiDB 0.1.17

Дата: 2026-10-21. Проверка исходного кода и автоматических сценариев; не заменяет ручную проверку установленного расширения.

## Область проверки

- Подключения, смена сессии, хранение и маскирование credentials, TLS/SSH.
- Граница webview → extension host, сериализация начального состояния и CSP.
- Read-only ограничения, адресация мутаций по ключам, preview, транзакции, проверка результата и неоднозначные исходы.
- Ограничение результатов, отмена/таймауты, пагинация и сохранность экспортируемых данных.
- SQLite worker/runtime, проверка скачиваемых архивов, сборка и упаковка.

## Исправления по порядку

### 1. Redis продолжал чтения после отмены или таймаута

`readTablePage` не передавал сигнал отмены в получение клиента, SCAN и чтение значений. После сообщения о таймауте операция могла продолжать отправлять команды серверу.

Исправлено: передача сигнала в SDK, прекращение ожидания уже отправленных команд, проверки до/после асинхронных чтений и остановка очереди параллельных чтений. Поздний ответ не запускает дальнейшую работу. Проверены отмена до запуска, во время SCAN/TYPE, таймаут, повторный запрос и настоящий транспорт node-redis.

Ограничение: уже отправленная Redis-команда может завершиться на сервере; отмена ожидания не означает её серверную отмену.

### 2. Повторы SCAN становились дубликатами строк и экспорта

Redis допускает повтор одного ключа внутри и между ответами SCAN. Раньше такие ответы попадали в пагинацию как отдельные записи и искажали счётчик и экспорт.

Исправлено: дедупликация точных ключей до сортировки/пагинации. Лимит уникальных ключей дополнен независимым ограничением в 5 000 запросов SCAN и обнаружением повторяющихся курсоров. Это предотвращает бесконечный обход при пустых/повторяющихся ответах. Проверены оба режима сортировки, экспорт, лимиты, циклический курсор и пустые ответы.

Полный прогон выявил зависание первого варианта дедупликации на старом моке с бесконечно повторяющимся курсором; ограничение итераций и отдельные регрессионные тесты добавлены до завершения ревью. Тест ограничения количества ключей теперь моделирует продвижение курсора и разные ключи; патологический случай проверяется отдельно и должен завершаться явной ошибкой.

### 3. Экспорт пропускал разные Unicode-ключи

Разные ключи в NFC/NFD могут давать `localeCompare(...) === 0`. При другом порядке SCAN на следующей странице экспорт мог записать один ключ дважды и потерять другой, даже без изменения данных.

Исправлено: точное сравнение строк при равенстве локализованной сортировки. Проверено экспортом по одной записи на страницу с чередующимся порядком SCAN, включая сортировку по одинаковым значениям.

## Границы заключения

- Redis-экспорт не является транзакционным снимком изменяющегося keyspace.
- Read-only переключатель приложения не заменяет серверные права; ограничения MSSQL/Oracle описаны в README.
- Нужен ручной smoke-тест свежего VSIX в настоящем VS Code на целевых ОС: установка, подключения, запрос, редактирование, отмена, экспорт и перезапуск. Использовать `docs/manual-testing-release-checklist.md`.
- Автоматический прогон выполнен на macOS / Node.js 26.12.0. Проект extension-host использует тестовые VS Code API; это не ручная проверка Electron UI. Отдельный live-прогон MariaDB не выполнялся.
- Успешные автоматические тесты не доказывают отсутствие всех ошибок и не подтверждают непроверенные комбинации ОС/серверов/прав.
